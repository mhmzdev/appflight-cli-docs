## Upload errors

### APK limit reached (plan limit)

```
✗ Upload blocked — you've reached your APK limit for this app.
✗ Free plan: 5 APKs per app. Upgrade in the AppFlight mobile app.
✗ Settings → Subscription → Upgrade to First Class
```

**Exit code:** `8`

**Cause:** Your account has hit the APK-per-app limit for your current plan. The Economy (free) plan allows 5 APKs per app. Older builds are preserved, but no new ones can be added until you upgrade or delete existing builds.

**Fix:**
- **Upgrade:** Open the AppFlight mobile app → **Settings → Subscription → Upgrade to First Class**
- **Check your plan:** Run `appflight whoami` — the `plan:` field shows your current tier

Run with `--verbose` to see the full server response for more detail:

```bash
appflight upload --flavor stage --verbose
```

### Version already exists

```
✗ Version 1.0.0 already exists for com.myapp.stage.
✗ Bump the version or use --version.
```

**Cause:** You've already uploaded this version. AppFlight doesn't allow overwriting an existing build.

**Fix:** Bump the version and rebuild, or override at upload time:

<Tabs groupId="framework">
  <TabItem label="Flutter" value="flutter">

    Bump `version` in `pubspec.yaml` and rebuild, or override:

    ```bash
    appflight upload --flavor stage --version 1.0.1
    ```

  </TabItem>
  <TabItem label="React Native" value="react-native">

    Bump `versionName` / `versionCode` in `android/app/build.gradle` and rebuild, or override:

    ```bash
    appflight upload --flavor stage --version 1.0.1
    ```

  </TabItem>
  <TabItem label="Kotlin" value="kotlin">

    Bump `versionName` / `versionCode` in `app/build.gradle` and rebuild, or override:

    ```bash
    appflight upload --flavor stage --version 1.0.1
    ```

  </TabItem>
</Tabs>

### App not found

```
✗ App not found on AppFlight: com.myapp.stage
```

**Cause:** The package name in `appflight.json` doesn't match any app registered on AppFlight. The app
has to exist before the CLI can upload to it.

**Fix:**

```bash
appflight apps list                                        # is it there under a different name?
appflight apps create --package com.myapp.stage --name "My App"
```

Or check `appflight.json` for a typo in `packageName`. Note that `appflight init` offers to create an
unknown package for you when you are logged in.

---

### Package name already taken

```
✗ An app with package name "com.myapp.stage" already exists.
```

**Cause:** Another AppFlight user has already registered this package name. Package names are unique across the entire platform — the same rule that applies on the Google Play Store.

**Fix:** You cannot upload to a package name owned by someone else. If this is your app, contact AppFlight support or use a different package name.

### APK not found

<Tabs groupId="framework">
  <TabItem label="Flutter" value="flutter">

    ```
    ✗ APK not found at build/app/outputs/flutter-apk/app-stage-release.apk
    ✗ Did you forget to run `flutter build apk --flavor stage --release`?
    ```

    **Fix:**

    ```bash
    # Build first
    flutter build apk --flavor stage --release

    # Or point directly at your APK
    appflight upload --flavor stage --file path/to/app.apk
    ```

### APK path flavor mismatch

The `--flavors` flag uses the flavor name to derive the APK path. If your build output doesn't follow the expected pattern, the derived path may not match.

**Fix:** Edit `apkPath` in `appflight.json` to match your actual build output:

<Tabs groupId="framework">
  <TabItem label="Flutter" value="flutter">

    ```json
    "prod": {
      "packageName": "com.myapp",
      "apkPath": "build/app/outputs/flutter-apk/app-prod-release.apk"
    }
    ```

  </TabItem>
  <TabItem label="React Native" value="react-native">

    ```json
    "prod": {
      "packageName": "com.myapp",
      "apkPath": "android/app/build/outputs/apk/prod/release/app-prod-release.apk"
    }
    ```

  </TabItem>
  <TabItem label="Kotlin" value="kotlin">

    ```json
    "prod": {
      "packageName": "com.myapp",
      "apkPath": "app/build/outputs/apk/prod/release/app-prod-release.apk"
    }
    ```

  </TabItem>
</Tabs>

### Permission denied (org apps)

```
✗ Only admins and developers can upload to organization apps.
```

Or, when creating an app:

```
✗ Only admins and developers can create organization apps.
```

**Exit code:** `9`

**Cause:** Your account has the `member` role in the organization. Only `admin` and `developer` roles
can upload builds or create apps. This is enforced on the server, so the CLI and the mobile app apply
the same rule.

**Fix:** Ask an admin to update your role in the AppFlight app → **Settings → Team**. A role change is
genuinely app-only.

## Auth errors

### Not logged in

```
✗ Not logged in. Run `appflight login` or set APPFLIGHT_API_KEY.
```

**Fix:**

```bash
# Interactive login
appflight login

# Or set env var (CI/CD)
export APPFLIGHT_API_KEY=appflight_xxxxxxxxxxxx
```

---

### API key invalid or revoked

```
✗ API key rejected. Check it and try again.
```

**Cause:** The key was revoked, or copied incorrectly.

**Fix:**
1. Run `appflight keys list` and check the key is still there
2. If it is gone, mint a replacement — `appflight keys create --name <label>` for CI, or
   `appflight login` again for this machine
3. If you are in CI, confirm `APPFLIGHT_API_KEY` holds the whole key, including the `appflight_` prefix

---

### Email not verified

```
✗ Check your inbox to verify your email, then run `appflight login` again.
```

**Exit code:** `6`

**Cause:** The account exists but the email has not been confirmed. The CLI cannot mint an API key for
an unverified account.

**Fix:** Open the verification link, then run `appflight login` again. Lost the email?

```bash
appflight signup --resend you@example.com
```

`--resend` also prompts for your password — sending the link requires a fresh sign-in, not just the
address.

---

### Set a password in the app first

```
✗ Set a password in the AppFlight app before using the CLI: Settings → Account.
```

**Exit code:** `6`

**Cause:** An organization admin created your account with a temporary password, so you must replace it
yourself before it can be used anywhere else.

**Fix:** Sign in to the AppFlight app, set your own password under **Settings → Account**, then run
`appflight login`. This one really is app-only.

---

### CI detected — refusing to prompt for a password

```
✗ CI detected — refusing to prompt for a password.
  Use `appflight login --key <key>` with a CI-scoped key (see `keys create`) or set APPFLIGHT_API_KEY instead.
```

**Exit code:** `64`

**Cause:** The `CI` environment variable is set. There is no one at a keyboard to type a password, so
`login` refuses rather than hanging.

**Fix:** Use a key made for CI:

```bash
appflight keys create --name "github-actions"   # on your machine, once
export APPFLIGHT_API_KEY=appflight_xxxxxxxxxxxx  # in your pipeline's secrets
```

See [GitHub Actions](/ci/github-actions) or [Codemagic](/ci/codemagic). Do not reuse the key `login`
minted for your laptop — the next `login` there revokes it.

---

### logout could not revoke the key

```
✗ Could not revoke this key against the "prod" environment (key not found). If you logged in with a different --env, retry logout with that one. Credentials were not removed.
```

**Exit code:** `6`

**Cause:** The stored key does not resolve against the environment `logout` ran against, so `logout`
cannot tell whether it is revoking the right thing.

**Fix:** The credentials file is kept on purpose — it may be the only record of a key that is still
live. Re-run `logout` against the environment you logged in with. If you are unsure, list your keys
with `appflight keys list` and revoke by prefix.

## Init errors

### Invalid package name format

```
✗ Invalid: "com.MyApp.Stage"
  Must be lowercase, dot-separated, at least 2 segments.
  Example: com.mycompany.myapp
```

**Rules:**
- All lowercase
- Dot-separated with at least 2 segments
- Letters, digits, and underscores only
- Cannot be `com.example.app`

---

### Spaces after commas in --flavors

```bash
# Wrong — shell splits on the space, second package is dropped silently
appflight init --flavors stage:com.myapp.stage, prod:com.myapp

# Correct — no spaces
appflight init --flavors stage:com.myapp.stage,prod:com.myapp
```

---

### appflight.json already exists

```
⚠ appflight.json already exists. Use --force to overwrite.
```

**Fix:**

```bash
appflight init --flavors stage:com.myapp.stage,prod:com.myapp --force
```
